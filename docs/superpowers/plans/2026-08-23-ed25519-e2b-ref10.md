# Ed25519 E2b — ref10 vendored behind the seam Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `AXL_PK_ED25519` real — vendor OpenSSH's public-domain ref10,
add it as an `AxlPkProvider` behind the weak-symbol seam E2a built, implement
RFC 8410 DER for it, and prove the security-relevant refusals actually fire.

**Architecture:** E2a left a finished seam: `_axl_pk_provider_for` already
resolves `AXL_PK_ED25519` through a weak symbol, `der_import_any` already
offers DER bytes to each provider in turn, and every public entry point already
dispatches. **This phase adds a provider and edits no dispatcher.** The vendored
code is one file exporting three symbols; everything else in it is `static`.

**Tech Stack:** C (C11, `-Wall -Wextra`, clang-tidy), OpenSSH's ref10
(public domain), mbedTLS 3.6.3 for SHA-512, QEMU-hosted UEFI unit tests.

**Spec:** `docs/superpowers/specs/2026-08-21-ed25519-design.md` — §2 (why
vendored), §4 (the 30 KB problem and the seam), §5 (the extension axes),
**§6b** (what the amalgamated source forecloses), §7 (testing), **§8 (security
review is a merge gate)**, §9 (non-goals, including RFC 8410 DER being in
scope), §11's E2b row.

## Global Constraints

- **§8 is a MERGE GATE.** No merge without an independent review of the vendored
  code's provenance, the canonical-S and small-order checks, and the dispatch.
  This is network-reachable crypto in firmware with no OS isolation beneath it.
  The final task exists to request that review.
- **Do not modify the vendored source.** Everything E2b needs is achievable by
  supplying the three externals it calls and wrapping its three exports. If you
  believe an edit is required, **stop and report** — a local patch to vendored
  cryptographic code is a disclosure obligation (the libvterm lesson: eight
  undisclosed patches were an unmet licence obligation) and it makes every
  future resync a merge.
- **Do not edit the dispatcher.** `src/net/axl-pk-verify.c` should need no
  change. If you find one necessary, that is a finding about E2a's seam and it
  should be reported, not worked around.
- **Test-first** for every behaviour: write the test, confirm RED, implement,
  confirm GREEN, sabotage.
- **Exact-string assertions for output.** `axl_strcmp(...) == 0`, never
  `axl_strstr`. **No `test_check(true, …)`** tautologies.
- **Leaks fail the run.** The harness greps for `=== AxlMem leak report:` and
  also fails a binary that prints no verdict.
- Style: `axl_snake_case`, `AxlPascalCase`, `AXL_SCREAMING_CASE`; 4-space
  indent; K&R braces; no space before parens; multi-line signatures. No
  `(void)`-cast on discarded call returns. **No lines containing only spaces or
  tabs.** These apply to **our** code; the vendored file keeps its own style.
- **C file order:** header comment, includes, macros, types, globals, static
  prototypes, implementations.
- **Commit with explicit pathspecs**, never `git add -A`. `git status` first —
  untracked `SCRATCH.txt` and six `docs/AXL-*.md` belong to the repo owner.
- **No references to Claude** in commit messages or committed content; no
  personal hostnames or LAN IPs.
- **aa64 is `./test/integration/test-axl.sh --arch AARCH64`** — an `ARCH=aa64`
  env var is ignored and silently re-runs X64. Check the banner.
- **Never `TEST_APPS_ONLY` for evidence or a sabotage** — a filtered run's count
  sits below the ratchet baseline, so the harness fails on the ratchet rather
  than on your change and you get "detected" for the wrong reason.
- Ratchet is **10808** and rises as you add assertions. If it drops, report.
- Do not `git push`.

### The negative checks are ALREADY in the vendored code

`crypto_sign_ed25519_open` opens with:

```c
  if (smlen < 64) goto badsig;
  if (sm[63] & 224) goto badsig;                          /* high bits of S */
  if (sc25519_inrange(sm+32)) goto badsig;                /* S >= L */
  if (ge25519_unpackneg_vartime(&get1,pk)) goto badsig;   /* non-canonical pk */
  if (ge25519_isneutral_vartime(&get1)) goto badsig;      /* small-order pk */
```

**So Task 4's job is to prove each is reachable through our wrapper, not to add
them.** That is a much better position than the spec anticipated, and it is why
Task 4 sabotages each check individually rather than writing new ones.

### The API shape you must adapt around

`crypto_sign_ed25519_open` uses NaCl's **combined** convention: it takes
`sm = signature || message` and writes the recovered message into an output
buffer the caller sizes at `smlen`. Our `AxlPkProvider.verify` is **detached**
— `(msg, msg_len, sig, sig_len)`.

So the adapter needs two scratch buffers of `sig_len + msg_len` each. Task 3
specifies how; do not invent a different scheme.

   generated headers and source files by Markus Friedl. Placed in the
   public domain."), openssh-portable V_10_5_P1, commit b3f73442.

   Reduced to what ed25519.c actually uses: the crypto_int/uint typedefs,
   the SHA-512 digest size, the Ed25519 sizes, and the three entry points.
   Upstream's `#include "includes.h"` is dropped -- it pulls OpenSSH's
   autoconf world, which does not exist here -- and `randombytes` is left
   for src/net/axl-ed25519-glue.c to define rather than macro-mapped to
   arc4random_buf.

   No other change. See deps/ed25519-ref10/README.md. */

#ifndef crypto_api_h
#define crypto_api_h

#include <stdint.h>
#include <stdlib.h>

typedef int8_t   crypto_int8;
typedef uint8_t  crypto_uint8;
typedef int16_t  crypto_int16;
typedef uint16_t crypto_uint16;
typedef int32_t  crypto_int32;
typedef uint32_t crypto_uint32;
typedef int64_t  crypto_int64;
typedef uint64_t crypto_uint64;

#define crypto_hash_sha512_BYTES 64U

int crypto_hash_sha512(unsigned char *, const unsigned char *,
    unsigned long long);

#define crypto_sign_ed25519_SECRETKEYBYTES 64U
#define crypto_sign_ed25519_PUBLICKEYBYTES 32U
#define crypto_sign_ed25519_SEEDBYTES      32U
#define crypto_sign_ed25519_BYTES          64U

int crypto_sign_ed25519(unsigned char *, unsigned long long *,

    const unsigned char *, unsigned long long, const unsigned char *);
int crypto_sign_ed25519_keypair_from_seed(unsigned char *, unsigned char *,

void randombytes(unsigned char *, unsigned long long);
void explicit_bzero(void *, size_t);

- [ ] **Step 5: Write the three externals**

Create `src/net/axl-ed25519-glue.c`. It is **ours**, so it follows this tree's
style:

```c
/* SPDX-License-Identifier: Apache-2.0 */
/* Copyright 2026 AximCode */

/** @file axl-ed25519-glue.c
    The three externals the vendored ref10 calls but does not define.

    deps/ed25519-ref10/ed25519.c is byte-identical to OpenSSH's, which
    means it expects OpenSSH's environment: a SHA-512, a scrub, and a
    random source. Supplying them here rather than patching the vendored
    file is what keeps a resync a copy rather than a merge -- see the
    design spec's §6b for what a local patch to that file would cost.
**/
```

- **`crypto_hash_sha512(out, in, inlen)`** — over
  `axl_compute_checksum_digest(AXL_CHECKSUM_SHA512, …)`, which E1 added.
  Return 0 on success and -1 otherwise; ref10 ignores the return, so a failure
  must not silently produce a zero digest — if the checksum call fails, scrub
  `out` before returning.
- **`explicit_bzero(p, n)`** — a `volatile`-pointer loop the optimiser cannot
  elide. `src/data/axl-hmac.c`'s `secure_zero` is the in-tree pattern; do not
  call `axl_memset`, which the compiler may remove.
- **`randombytes(buf, len)`** — over `axl_crypto_rng()` and
  `mbedtls_ctr_drbg_random`. **On failure it must not return silently with an
  unfilled buffer** — ref10's `crypto_sign_ed25519_keypair` ignores the return
  and would generate a key from stack garbage. Scrub the buffer and, since the
  signature is `void`, make the failure loud: `axl_error` and leave the buffer
  zeroed, which produces a deterministic wrong key rather than a plausible one.
  Note in a comment that Task 3 does not route keygen through this path
  (it uses `keypair_from_seed`), so this is defence for a caller that reaches
  `crypto_sign_ed25519_keypair` directly.

- [ ] **Step 4: Write the provider**

`src/net/axl-pk-ed25519.c`. Define **no** `AXL_PK_PROVIDER_WEAK` — this is the
translation unit that *defines* the symbol, and the weak attribute belongs only
where the reference is made. Putting it here makes the definition weak inside
`libaxl.a` and `-u` stops being reliable; the contract's header says so.

**The SM adapter is the part to get right.** `crypto_sign_ed25519_open` takes
`sm = sig || msg` and writes a recovered message into a buffer the caller sizes
at `smlen`. So `verify` must:

```
n = sig_len + msg_len            /* sig_len is 64 */
sm = axl_malloc(n); m = axl_malloc(n)
copy sig into sm[0..64), msg into sm[64..n)
rc = crypto_sign_ed25519_open(m, &mlen, sm, n, key->u.ed25519.pk)
scrub and free both
return rc == 0 ? AXL_OK : AXL_ERR
```

Both buffers are required — ref10 writes into `m` unconditionally, including
`memset(m, 0, smlen)` on the failure path. **Do not** alias them.

Failure of either allocation returns `AXL_ERR`. Do not use a stack buffer sized
by `msg_len`; UEFI stacks are not generous and §10 tracks peak stack.

`sign` mirrors it: `crypto_sign_ed25519` produces `sm = sig || msg`, so
allocate `64 + msg_len`, call, and copy the first 64 bytes out.

Vtable members:

- `key_init` — nothing to initialise; the union arm is already zeroed. Return
  true. (A NULL member would also be legal, but an explicit true documents the
  intent.)
- `key_free` — **must zeroize `sk`.** `axl_pk_key_free` promises publicly that
  it zeroizes private key material, and for this provider the arm *is* the
  secret. Use the same non-elidable scrub as the glue file, not `axl_memset`.
- `keygen` — `crypto_sign_ed25519_keypair_from_seed` over 32 random bytes from
  `axl_crypto_rng()`. Do **not** call `crypto_sign_ed25519_keypair`; going
  through the seed keeps the random source in our code where its failure is
  checkable.
- `sign` / `verify` — as above. Both must return `AXL_ERR` unless
  `axl_pk_sig_params_ok(mode, ctx, ctx_len)`; the dispatcher already checks, but
  the contract permits a provider to assume that, so simply do not re-check —
  **and do not ignore `fmt`**: Ed25519 has one signature encoding, so follow the
  contract's rule that such a provider ignores `fmt`, as RSA does.
- `raw_public_import` / `raw_public_export` — 32 bytes, exactly.
- `raw_private_import` — 32-byte seed, if you took Step 2's recommendation.
- DER members — leave **NULL** for now. Task 5 fills them, and the contract
  makes members optional precisely so a partial provider is legal.

### Task 5: RFC 8410 DER
