# Ed25519 E2a — the AxlPk provider seam Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restructure `AxlPkKey` from "is an `mbedtls_pk_context`" into a tagged
union behind an `AxlPkProvider` vtable, carrying **only** the existing ECDSA and
RSA algorithms, so that E2b can add Ed25519 as a provider rather than as surgery.

**Architecture:** `src/net/axl-pk-verify.c` currently defines
`struct AxlPkKey { mbedtls_pk_context pk; AxlPkAlg alg; bool has_private; }` —
the key *is* an mbedTLS context, and 24 sites reach through `->pk`. This phase
turns that member into a tagged union with one arm (`mbedtls`), routes every
site through a provider vtable selected by `key->alg`, and fixes two
silent-wrong-default helpers. **It adds no cryptography**: the same mbedTLS
calls run in the same order, so the existing ECDSA/RSA vectors are the proof of
correctness. It also adds one genuinely new public API — raw public-key
import/export — which is implementable and testable for ECDSA today, so E2a
ships nothing speculative.

**Tech Stack:** C (C11, `-Wall -Wextra`, clang-tidy), mbedTLS 3.6.3 (vendored,
compiled unconditionally), QEMU-hosted UEFI unit tests.

**Spec:** `docs/superpowers/specs/2026-08-21-ed25519-design.md` — §4b (the seam
following `axl-log-dispatch.h`), **§4b-bis** (what the seam costs to reach —
written specifically for this phase), §5 (the two-axis extension shape), §8
(security review is a gate), §11's E2a row.

### Task order is a safety property

Same discipline that made E1 provable. Task 2 removes the silent-wrong-default
helpers **before** the tagged union exists, so the refactor is never reasoning
about a helper that lies. Task 3 lands the union with the mbedTLS arm as the
only arm, so every existing test still exercises the same code path. Task 4
introduces the vtable with exactly one provider registered. Only then does
Task 5 add new API. At no point does a half-built provider serve a real call.

In `include/axl/axl-crypto.h`, after `axl_pk_key_load_public`'s declaration, add:

```c
/**
 * @brief Import a public key from its raw, algorithm-native encoding.
 *
 * "Raw" means the encoding the algorithm's own ecosystem uses on the
 * wire, not a DER container:
 *
 * - #AXL_PK_ECDSA_P256 / #AXL_PK_ECDSA_P384 — an uncompressed SEC1
 *   point, `0x04 || X || Y`: 65 bytes for P-256, 97 for P-384.
 * - #AXL_PK_ED25519 — the 32-byte compressed point (RFC 8032 §5.1.2).
 *   **Not supported yet**; see axl_pk_alg_available().
 * - #AXL_PK_RSA has no meaningful raw form and is always rejected —
 *   use axl_pk_key_load_public() with DER.
 *
 * Use axl_pk_key_load_public() when you have a DER
 * `SubjectPublicKeyInfo` instead.
 *
 * @return a new public-only key handle, or NULL if @a alg has no raw
 *     form, @a raw is NULL, @a len is wrong for @a alg, the bytes are
 *     not a valid point, or the algorithm is unavailable in this build.
 */
AxlPkKey *
axl_pk_key_from_raw_public(
    AxlPkAlg       alg,  ///< algorithm the bytes encode
    const uint8_t *raw,  ///< raw public key bytes
    size_t         len   ///< length of @a raw in bytes
);

/**
 * @brief Export a public key in its raw, algorithm-native encoding.
 *
 * The inverse of axl_pk_key_from_raw_public(), and the same encodings.
 * Works on a public-only handle and on one that also holds a private
 * key; only public material is ever written.
 *
 * Uses the output-buffer protocol of axl_pk_key_get_private_der(): call
 * with @a out NULL to learn the required size in @a *len, then again
 * with a buffer at least that large.
 *
 * @return #AXL_OK on success; #AXL_ERR if @a key or @a len is NULL, the
 *     key's algorithm has no raw form, or @a out is non-NULL and
 *     @a *len is too small (in which case @a *len is set to the size
 *     needed).
 */
int
axl_pk_key_get_raw_public(
    const AxlPkKey *key,  ///< key handle
    uint8_t        *out,  ///< destination, or NULL to query the size
    size_t         *len   ///< [in/out] buffer size / bytes written
);

/**
 * @brief Whether a public-key algorithm is usable in this image.
 *
 * Distinct from axl_pk_available(), which reports whether the
 * public-key layer is present at all. An algorithm can be absent from
 * an image that has the layer: #AXL_PK_ED25519 is opt-in at link time,
 * because its precomputed table is ~30 KB of resident `.rodata` that a
 * firmware driver should not carry unasked.
 *
 * Check this before axl_pk_key_new() when the algorithm is chosen at
 * runtime — it distinguishes "not linked" from "key generation
 * failed", which both otherwise surface as NULL.
 *
 * @return true if @a alg can be used in this image.
 */
bool
axl_pk_alg_available(
    AxlPkAlg alg  ///< algorithm to query
);
```

- [ ] **Step 2: Write the provider vtable header**

Create `src/net/axl-pk-provider.h`:

```c
/* SPDX-License-Identifier: Apache-2.0 */
/* Copyright 2026 AximCode */

/** @file axl-pk-provider.h
    The per-algorithm vtable behind AxlPkKey.

    AxlPkKey used to *be* an mbedtls_pk_context. Ed25519 cannot be one
    — mbedTLS 3.6.3 has no twisted-Edwards curve at all — so the key
    became a tagged union and every entry point routes through the
    vtable below, selected by the key's algorithm.

    A provider is reached through a WEAK symbol so that an algorithm
    nothing calls costs an image nothing. That matters for exactly one
    algorithm today: Ed25519's precomputed base-point table is 30,720
    bytes of resident .rodata, and axl_pk_key_new() is a dispatcher
    every AxlPk consumer calls, so a strong reference would pull the
    table into every image. See the design spec §4.

    Not a public header — do not include from outside src/net/.
**/

#ifndef AXL_PK_PROVIDER_H
#define AXL_PK_PROVIDER_H

#include <axl/axl-crypto.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

/* The weak attribute must be applied ONLY where the reference is made.
   Putting it on a declaration in the translation unit that also
   DEFINES the symbol makes the definition weak, which leaves it weak
   inside libaxl.a and makes `-u` unreliable. axl-pk-verify.c defines
   this before including the header; a provider implementation does
   not. One prototype either way, so the two cannot drift. */
#ifdef AXL_PK_PROVIDER_WEAK
#  define AXL_PK_PROVIDER_DECL __attribute__((weak))
#else
#  define AXL_PK_PROVIDER_DECL
#endif

typedef struct AxlPkKey AxlPkKey;

/**
 * Signature mode. Design spec §5 requires this on `sign`/`verify`
 * from the start: Ed25519ph and Ed25519ctx are the SAME curve and the
 * SAME key as pure Ed25519, differing only by a prehash and a
 * domain-separation string. With a mode and a context in the shape,
 * they become later enum values on an existing provider; without
 * them they are a redesign.
 *
 * Only #AXL_PK_SIG_PURE exists today and every provider must REJECT a
 * non-empty context rather than ignore it — an ignored context
 * silently produces signatures that verify under the wrong domain,
 * which is the failure this parameter exists to make impossible.
 *
 * Internal for now. E2b decides whether this becomes public, once
 * Ed25519 gives the mode something to select between.
 */
typedef enum {
    AXL_PK_SIG_PURE = 0  /**< sign/verify the message itself (RFC 8032 §5.1) */
} AxlPkSigMode;

/**
 * Per-algorithm operations. Every member must be non-NULL: a provider
 * that cannot do something supplies a stub returning the documented
 * failure, so no call site needs a NULL check. `raw_public_import` and
 * `raw_public_export` reject with AXL_ERR for an algorithm with no raw
 * form (RSA).
 */
typedef struct {
    /** Algorithm this provider serves; the dispatcher matches on it. */
    AxlPkAlg alg;

    /** Initialise @a key's union arm. Returns false on failure. */
    bool (*key_init)(AxlPkKey *key);

    /** Release whatever key_init and the loaders allocated. */
    void (*key_free)(AxlPkKey *key);

    /** Generate a fresh keypair into an initialised @a key. */
    bool (*keygen)(AxlPkKey *key);

    /** Sign @a msg. Follows axl_pk_key_sign()'s buffer protocol.
        Must return AXL_ERR unless @a mode is AXL_PK_SIG_PURE and
        @a ctx is NULL with @a ctx_len 0. */
    int (*sign)(const AxlPkKey *key, const uint8_t *msg, size_t msg_len,
                AxlPkSigFormat fmt, AxlPkSigMode mode,
                const void *ctx, size_t ctx_len,
                uint8_t *sig, size_t *sig_len);

    /** Verify @a sig over @a msg. Returns AXL_OK only on a good
        signature, and only under the same mode/context rule as sign. */
    int (*verify)(const AxlPkKey *key, const uint8_t *msg, size_t msg_len,
                  AxlPkSigMode mode, const void *ctx, size_t ctx_len,
                  const uint8_t *sig, size_t sig_len);

    /** Import a raw public key. Returns false on any malformed input. */
    bool (*raw_public_import)(AxlPkKey *key, const uint8_t *raw, size_t len);

    /** Export the raw public key, size-query protocol as documented. */
    int (*raw_public_export)(const AxlPkKey *key, uint8_t *out, size_t *len);
} AxlPkProvider;

/* One extern per provider. The mbedTLS provider serves ECDSA and RSA
   and is referenced strongly — every build has mbedTLS. Ed25519's is
   weak and NULL unless the image opted in with
   `-u _axl_pk_provider_ed25519`. */
extern const AxlPkProvider _axl_pk_provider_mbedtls;
AXL_PK_PROVIDER_DECL extern const AxlPkProvider _axl_pk_provider_ed25519;

/**
 * Look up the provider for @a alg, or NULL if this image has none.
 * NULL is the fail-closed answer every entry point turns into a NULL
 * handle or AXL_ERR.
 */
const AxlPkProvider *
_axl_pk_provider_for(
    AxlPkAlg alg  ///< algorithm to resolve
);

#endif /* AXL_PK_PROVIDER_H */
```

**Why this is a defect, not a cleanup.** Both are ternaries with a silent

```c

{
```

returns 32 — both silently, because a ternary gets no `-Wswitch`. This is the
same class of defect E1 spent four commits removing from

already a valid enumerator that a caller can pass today.

- [ ] **Step 4: Make both helpers fail closed and implement `axl_pk_alg_available`**

In `src/net/axl-pk-verify.c`, replace both helpers:

```c
/* The message-digest a key-handle algorithm signs over: the ECDSA hash
   follows the curve (P-256 -> SHA-256, P-384 -> SHA-384); RSA PKCS#1 v1.5
   here is always SHA-256 (RS256). Returns MBEDTLS_MD_NONE for an algorithm
   that does not sign over a prehash at all -- Ed25519 hashes the message
   internally, twice -- so a caller that forgets to check gets a refusal
   from mbedtls rather than a signature over the wrong digest. */
static mbedtls_md_type_t
md_for_alg(AxlPkAlg alg)
{
    switch (alg) {
    case AXL_PK_ECDSA_P256:
    case AXL_PK_RSA:          return MBEDTLS_MD_SHA256;
    case AXL_PK_ECDSA_P384:   return MBEDTLS_MD_SHA384;
    case AXL_PK_ED25519:      return MBEDTLS_MD_NONE;
    }
    return MBEDTLS_MD_NONE;
}

/* The ECDSA curve order size in bytes for a raw r||s signature. Zero for
   an algorithm whose signature is not r||s, which is every non-ECDSA one. */
static size_t
ec_order_bytes(AxlPkAlg alg)
{
    switch (alg) {
    case AXL_PK_ECDSA_P256:   return AXL_P256_ORDER_BYTES;
    case AXL_PK_ECDSA_P384:   return AXL_P384_ORDER_BYTES;
    case AXL_PK_RSA:
    case AXL_PK_ED25519:      return 0;
    }
    return 0;
}
```

in a `default:` label, so `-Wswitch` still names them when a fifth algorithm is
added. That is the idiom E1 established for `axl_checksum_type_get_length`.

### Task 3: `AxlPkKey` becomes a tagged union

**Files:**
- Modify: `src/net/axl-pk-verify.c` (the struct and all 24 `->pk` sites)

- [ ] **Step 1: Restructure the type**

- [ ] **Step 2: Add the accessor and route every site through it**

Add beside the struct:

```c
/* Every mbedTLS-arm site goes through this rather than reaching into
   the union, so the tag check lives in one place. Returns NULL when
   `alg` does not name the mbedTLS arm, which every caller treats as a
   refusal. The const_cast is confined here: mbedTLS's API takes a
   non-const context even for operations that do not mutate the key. */
static mbedtls_pk_context *
mbedtls_ctx(const AxlPkKey *key)
{
    if (key == NULL) {
        return NULL;
    }
    switch (key->alg) {
    case AXL_PK_ECDSA_P256:
    case AXL_PK_ECDSA_P384:
    case AXL_PK_RSA:
        return (mbedtls_pk_context *)&key->u.mbedtls;
    case AXL_PK_ED25519:
        return NULL;
    }
    return NULL;
}
```


Three shapes, and each converts mechanically:

- **`mbedtls_pk_init(&k->pk)`** and **`mbedtls_pk_free(&key->pk)`** — these run
  before the tag is set and after it stops mattering, so they address the arm
  directly: `mbedtls_pk_init(&k->u.mbedtls)`, `mbedtls_pk_free(&key->u.mbedtls)`.
- **Sites that already take a local** (`mbedtls_pk_context *pk = (mbedtls_pk_context *)&key->pk;`)
  — replace with `mbedtls_pk_context *pk = mbedtls_ctx(key);` **and add a NULL
  check returning the function's documented failure** (`NULL`, `AXL_ERR`, or
  `false` — match what the function already returns on bad input).
- **Sites that reach inline** (`mbedtls_pk_ec(k->pk)`, `mbedtls_pk_setup(&k->pk, …)`,

  NULL-check it, then use it.

**Do not skip a NULL check because "alg is obviously ECDSA here."** The tag is
what makes the union safe, and a site that assumes rather than checks is the
one that breaks in E2b.

## After E2a

E2a is done when both arches are green with **every pre-existing ECDSA and RSA
vector unchanged**, `verify.sh` is green, the docs build warning-free, and the
whole-branch review is applied.

The deliverable for E2b is a seam where adding Ed25519 is: one provider object
in a new `src/net/axl-pk-ed25519.c`, one `-u` flag, and the union's second arm.
No entry point changes.

**Two things E2a deliberately does not do:**

- **No Ed25519, not even partially.** Every provider lookup for it returns NULL.
  §8 makes new cryptography a security-review gate, and mixing it into a
  refactor is what this split exists to prevent.
- **No RFC 8410 DER.** It is in scope for the project (§9) but belongs with the
  Ed25519 key handling it serves, in E2b.

**Carried into E2b — two things, both found during E2a and neither closable
inside it:**

- The spec's §4c gate (`check-ed25519-linkage`) is E3, but E2b is when the weak
  symbol first has a definition to be weak *against* — so E2b's report should
  record whether an image that does not opt in measures zero ref10 bytes, even
  though the gate that enforces it lands later.
- **`md_for_alg` and `ec_order_bytes`'s fail-closed branches are untested, and
  cannot be tested in E2a.** Task 2's review traced this: no public constructor
  can produce a live `AxlPkKey` with `alg == AXL_PK_ED25519`, because
  `axl_pk_key_new` rejects and frees before returning. So reverting either
  helper to its old silent ternary would break **no** test in the suite. That is
  acceptable *here* — the guard is being installed before the hazard arrives,
  which is the whole point of the task ordering — but it means the assertion
  that proves it fires must come with E2b, when an Ed25519 key first exists.
  **E2b must add a test that drives a real Ed25519 key through the signing
  path and pins that neither helper returns a P-256 answer.** Do not close
  this by adding a test-only backdoor to construct such a key in E2a; a hook
  into production code to reach an unreachable state costs more than the gap.
